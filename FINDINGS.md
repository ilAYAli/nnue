# NNUE Training Research Findings

Research conducted 2026-08-06. Five parallel agents investigated the Enyo trainer
source, all engines in ~/source, published NNUE research (2024–2025), the
Stockfish training pipeline, and bullet-trainer best practices.

## Summary

The corpus is already competitive. The bottleneck is the training configuration
and loss function, not the data. Three code-level changes (SCReLU, cubic loss,
AdamW beta1) and one config change (WDL) have strong external evidence and have
never been tested in Enyo.

---

## 1. WDL for lc0 data: 0.3 is catastrophic; correct value is 0.05–0.075

**Priority: High. Updated with empirical evidence from enyo-scc-1.2.0-rc1 and enyo-lc-1.0.0-rc1.**

The target formula in spike_trainer is:

    target = (1 - wdl) * sigmoid(eval / eval_scale) + wdl * game_result

**Original hypothesis** (2026-08-06): WDL=0.05 is too low; try WDL=0.3 to exploit
high-quality lc0 game results. This hypothesis is **DISPROVED** by subsequent experiments.

**Empirical results (2026-08-07/08):**
- `enyo-scc-1.2.0-rc1` (WDL=0.3, scc corpus, continue_from rc1.1): elo=-223.9 absolute — 87 Elo worse than the founding net
- `enyo-lc-1.0.0-rc1` (WDL=0.3, lc0 self-play data, scratch): elo≈-310 at 436/4000 games — catastrophic, abandoned
- `enyo-scc-1.0.0-rc1` (WDL=0.05, scc corpus, scratch): elo=-93.2 vs rc10 — correct behavior for a founding net

**Root cause**: ~53% of lc0 self-play positions are within 100cp of 0. For these balanced
positions, SF oracle eval is near-zero (target via sigmoid ≈ 0.5) but lc0 MCTS game outcome
is high-variance (can be win, draw, or loss regardless of position quality). At WDL=0.3,
30% of training signal comes from this noisy game outcome, flooding training with contradictory
labels for the majority of positions. The net learns near-uniform output.

At WDL=0.05, the SF oracle eval dominates (95% weight) and game outcome is a small
perturbation — the net can learn correctly.

**WDL sensitivity to data type:**
- lc0 T91 / lc0 self-play data with SF oracle relabels: WDL ≤ 0.1, specifically 0.05–0.075
- Pure SF self-play (positions generated by SF, not relabeled): WDL=0.3 may be appropriate,
  matching nnue-pytorch's lambda=0.75

**In-flight ablation** (2026-08-07–08):
- pwa-llm: `enyo-lc-1.0.0-rc1` WDL=0.075, plain ReLU scratch
- pwa-5090: `enyo-lc-1.0.0-rc1` WDL=0.05, plain ReLU scratch
- Decision rule: use SF gate absolute Elo (4000 games, CI≈±19) as primary comparator
  since SPRT stops at different game counts. Less negative absolute Elo wins. If
  difference < CI overlap (i.e. |Elo_llm - Elo_5090| < 25), default to WDL=0.05:
  lower WDL = less MCTS noise contamination = safer by the root-cause analysis above.

## 2. Cubic loss: +14.8 Elo at fixed nodes (one-line change)

**Priority: High. Requires trainer rebuild.**

July 2024 NNUE research (asteri.sm/files/2024-07-15-nnue-research-02.html)
ran a direct game-match A/B across multiple architectures:

> Combined result: 14.81 Elo at fixed nodes, 6.82 Elo at STC.

Mechanism: `(sigmoid(output) - target)^3` instead of `^2`. Larger gradient for
large errors, smaller gradient for near-correct predictions — better-calibrated
pressure than MSE.

Current Enyo loss: `output.sigmoid().squared_error(target)`.
Required change: switch to cubic error in spike_trainer (one expression).
New export format is NOT required; this is a pure training change.
Never tested in Enyo.

## 3. SCReLU activation: equivalent to 50% larger network (architecture change)

SCReLU or a squared-clipped relative is common, but there are materially different architectures.

  ━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ─────────────  ─────────────────────  ────────────────────────────────────────────────────

  ─────────────  ─────────────────────  ────────────────────────────────────────────────────

  ─────────────  ─────────────────────  ────────────────────────────────────────────────────

  ─────────────  ─────────────────────  ────────────────────────────────────────────────────

  ─────────────  ─────────────────────  ────────────────────────────────────────────────────
   Reckless                        No    Pairwise FT followed by ordinary clipped ReLU
  ─────────────  ─────────────────────  ────────────────────────────────────────────────────
   berserk                         No    CReLU input followed by ordinary ReLU layers
  ─────────────  ─────────────────────  ────────────────────────────────────────────────────

  ─────────────  ─────────────────────  ────────────────────────────────────────────────────
   viridithas                      No    Pairwise CReLU FT followed by Hard-Swish/SwiGLU


**Priority: High. Requires accepted plain ReLU parent for initialize_from.**

June 2024 NNUE research (asteri.sm/files/2024-06-25-nnue-research-01.html):

> "a 1536-neuron CReLU net achieves the same final loss as a 1024-neuron SCReLU net"

Multiple engines reported 10–25+ Elo gains. SCReLU is now standard in every
competitive engine: Stormphrax uses SCReLU at L2, Stockfish uses SqrClippedReLU
at FC_0.

Current Enyo enyo-mode activation:
- L0: `max(0.0).min(127.0 * 32.0) / 32.0` — plain CReLU
- L1/L2: `.relu()` — plain ReLU

The `reckless` forward path in the same trainer file already has `.screlu()`.
Enabling it for the enyo path requires `dense_activation=relu-screlu-residual` +
`export_format=enyo-native-v4` in architecture.json and `initialize_from` in build.json.

**All prior Enyo SCReLU tests are INVALID:**
- scc-2.0.0-rc1 / rc2: trained with l2sb gradient **frozen**. Commit 81d319de (2026-08-07)
  fixed a FusePointwise IR compiler bug in bullet_lib that silently dropped gradient NodeIds.
  The `no_grad` workaround in main.rs is now removed. In those runs, the squared branch
  weights (l2sw) learned but the bias (l2sb) never updated — the activation was
  `relu(Wx + 0)^2` throughout training instead of `relu(Wx + b)^2`.
- Scratch SCReLU tests: WDL=0.3 catastrophe (separate from l2sb issue).

**First clean SCReLU test** will have: correct WDL (0.05–0.075), l2sb gradient working
(81d319de), and warm initialization from an accepted plain ReLU parent.
Blocked until: lc0 lineage produces an accepted net (passes SPRT vs rc10).

Cannot be combined with full-head (main.rs explicitly forbids
mixed_activation + FULL_HEADS).

**Test**: scratch round on scc corpus with SCReLU at L1/L2, new architecture
number. Never tested in Enyo.

## 4. AdamW beta1: 0.9 → 0.95 (~+4 Elo, one-line)

**Priority: Medium. Bundle with #2 and #3.**

Same July 2024 research measured ~4 Elo gain from this change alone. The
current trainer uses AdamW `..Default::default()` which sets beta1=0.9.
One-line change in AdamWParams. Too small to test standalone — bundle with
cubic loss and SCReLU.

## 5. final_lr: 200:1 decay ratio wastes the last 40% of every round

**Priority: Medium. Config change only.**

Current: `lr=0.001`, `final_lr=0.000005` → 200:1 ratio.
nnue-pytorch standard: 10:1 to 40:1.

With a 200:1 ratio, the LR falls below 1e-4 for the final ~40% of training.
The optimizer contributes almost no gradient signal for that period — pure
wasted compute.

**Change**: `"final_lr": 0.000025` (40:1 ratio) as a build.json override.
Apply immediately to all future rounds.

## 6. FullThreats — not closed, undertested

**Priority: Medium. Requires architecture + code + scratch round.**

Every competitive engine above ~3600 CCRL uses threat inputs (59,808 features
encoding piece-attack pairs) plus pawn-pair features (~4,560). The gap between
engines with and without these features is ~100+ Elo in architecturally
comparable comparisons (Berserk at L1=1024 without threats vs Stormphrax at
L1=1024 with threats).

Enyo tested FullThreats twice:
1. Slider-xray threats (simpler variant) — tested extensively in isolation, failed
2. FullThreats — tested combined with full-head, warm-started from rc10, at wdl=0.05

Test #2 was not a clean single-variable test. FullThreats + full-head changed
two variables simultaneously. The warm-start from a non-threats net means
threat weights start at zero while all others are at strong values — a difficult
initialization. And wdl=0.05 starved the threat-feature gradient.

**Clean test**: FullThreats alone, from scratch on scc corpus, after WDL fix.
This requires the FullThreats code (already merged in format v6) and a separate
architecture number. High variance — could add 50-100+ Elo if the previous
failures were training-configuration artifacts rather than fundamental.

## 7. What is already correct — do not change

- **Corpus composition**: 3.23B positions (Lc0 T91 converted + nodes5000pv2)
  is large and high-quality by external standards. The nnue-pytorch wiki
  explicitly describes Lc0-derived data as "generally producing better networks."
  T91 is stronger than the T60/T70 Stockfish uses.

- **nodes5000**: The nnue-pytorch wiki confirms nodes5000 ≈ depth9. Higher
  nodes (40k+) is not proven better and can introduce style bias. No change
  needed.

- **Filtering**: `quiet_only=true`, `min_ply=16` are correct and standard.
  `max_abs_cp=10000` is effectively no filter; no strong evidence for
  tightening it.

- **Cosine LR decay**: Standard and appropriate. nnue-pytorch uses step-wise
  decay (gamma=0.992/epoch) but both converge similarly.

- **Multiple dose-continuation rounds with fresh LR schedule**: Correct. The
  scratch-long chain confirmed this empirically before it appeared in SGDR
  literature. Do not merge rounds into one longer run.

- **SF oracle relabeling for self-play positions**: Correct at current strength
  (-140 vs SF). Self-distillation (using Enyo's own eval as labels) only
  becomes beneficial when the engine closes to within ~50 Elo of the oracle.

## 8. Reference architectures (from ~/source survey)

All engines at competitive strength share these properties:

| Feature | Enyo current | Competitive standard |
|---|---|---|
| L1 size | 1024 | 1024 (standard), 1536+ (Alexandria, SF) |
| Input buckets | 16 | 16 (standard), 32 (Stockfish) |
| Output buckets | 8 | 8 |
| L0 activation | CReLU | Pairwise CReLU + SCReLU |
| Loss | Squared | Cubic |
| Threat inputs | Off (failed tests) | Universal at top strength |
| Pawn-pair features | None | Stormphrax, viridithas, PlentyChess, SF |
| Skip connection L2→L3 | None | Stormphrax, PlentyChess |
| Full-head | Off (failed test) | Standard (all reference engines) |

Stormphrax (`(768×16→1024)×2→(16→32→1)×8`) uses SCReLU at L2, skip
connection at L3, threat inputs, pairwise CReLU — and trains exclusively on
self-generated data with bullet. PlentyChess uses 15B+ positions with
self-distillation.

## 9. Non-transitivity (the rc1 inversion)

`enyo-scc-1.1.0-rc1`: elo=-66.9 vs rc10 (parent-relative), elo=-238.7 vs SF
(absolute). Predicted absolute from parent-relative: approximately -206. Gap: ~32 Elo.

At 1500 games, CI on vs-SF ≈ ±25–30 Elo. Combined uncertainty on predicted
absolute is ±38–40 Elo. The 32-Elo discrepancy is within that range —
most likely measurement noise, possibly compounded by corpus clustering if the
shuffle hypothesis (rc2) is correct.

Genuine non-transitivity does exist in chess (arxiv 2412.14427) but is most
pronounced between engines of very different styles or rating levels. For
same-lineage engines at similar strength, transitivity holds approximately.

The 4000-game vs-SF absolute measurements (CI ~19 Elo) are the reliable ground
truth. Do not over-index on 1500-game absolute measurements.
